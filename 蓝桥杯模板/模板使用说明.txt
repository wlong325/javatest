蓝桥杯单片机赛前速查清单
==========================

赛场心法
--------
先跑通，再完善；先稳定，再炫技。

推荐做题顺序：
1. 先完整读题，圈出显示、按键、串口、报警、EEPROM、公式计算。
2. 再定义变量和页面状态，不急着写复杂逻辑。
3. 先把数码管显示跑通。
4. 再把按键功能跑通。
5. 然后写核心计算和报警逻辑。
6. 最后补串口、EEPROM、异常上报和边界细节。
7. 每完成一块就编译一次，能烧录验证就尽早验证。
一、拿到新题先做什么
------------------
1. 先读题目要求，圈出：显示页面、按键功能、串口协议、报警条件、EEPROM 保存要求。
2. 先不要动中断和底层驱动，优先改 Display_Proc()、Key_Proc()、Logic_Proc()、Uart_ParseOneCommand()。
3. 如果题目没有用到某个模块，可以先不删，只要不显示、不参与逻辑即可；时间紧时稳定优先。
4. 每完成一个大模块就编译一次，不要攒到最后一起查错。
5. 如果烧录后显示异常，优先检查 seg[] 是否越界、Code[] 下标是否正确、有没有在主循环直接写 P0/P2。

二、各功能应该改哪里
------------------
1. 数码管显示：改 Display_Proc()，只改 seg[0]~seg[7]，不要直接扫数码管。
2. 按键：改 Key_Proc()，短按看 key_down，松手看 key_up，长按/组合键参考按键注释模板。
3. 业务计算和报警：改 Logic_Proc()，比如阈值判断、液位计算、重量计算、状态切换。
4. LED：改 Led_Proc()，只修改 led。L1~L8 对应 0x01、0x02、0x04、0x08、0x10、0x20、0x40、0x80。
5. 继电器/蜂鸣器：改 Relay_Buzz_Proc()，继电器 bit4=0x10，蜂鸣器 bit6=0x40。
6. 串口查询/设置命令：改 Uart_ParseOneCommand()。
7. 串口主动异常上报：在 Logic_Proc() 置 uart_report_code 和 uart_report_flag，由 Uart_Report_Proc() 发送。
8. EEPROM 参数保存：改 EEPROM_SaveParams() 和 EEPROM_LoadParams()，不要在 while(1) 里连续写 EEPROM。

三、常用位值表
------------
bit0 = 0x01，bit1 = 0x02，bit2 = 0x04，bit3 = 0x08。
bit4 = 0x10，bit5 = 0x20，bit6 = 0x40，bit7 = 0x80。
置位：value |= 0x10。
清位：value &= ~0x10。
判断：if(value & 0x10)。

四、串口速查
----------
1. 普通命令：默认 UART_MULTI_CMD_ENABLE = 0。
2. 连续配置命令，例如 (D,2500)(T,235950)：把 UART_MULTI_CMD_ENABLE 改为 1。
3. 查询命令例如 (T?)，在 Uart_ParseOneCommand() 里拼回复。
4. 设置命令例如 (D,2500)，必须判断格式和范围，合法才修改变量。
5. 主动上报默认格式：[错误码,HHMMSS]\r\n，例如 [500,123456]。
6. 串口发送忙时不要强行覆盖 TX1_Buffer，先判断 B_TX1_busy == 255。

五、最容易踩的坑
--------------
1. 不要在中断里读 DS18B20、IIC、DS1302。
2. 不要用 Delay_nms() 做闪灯、按键等待、串口等待。
3. 不要在主循环里直接写 HC573/P0/P2 刷显示。
4. 不要让数组下标越界，尤其是 seg[]、RX1_Buffer[]、TX1_Buffer[]。
5. 不要忘记高位灭零时用 SEG_BLANK。
6. NE555 频率测量通常用 1 秒闸门，NE555_TASK_TIME 保持 1000 最稳。
7. 题目要求“上电后第一秒开始，间隔一秒采集频率”，通常理解为上电开始计数，1 秒后得到第一次频率，以后每秒更新一次。
8. EEPROM 写入要按事件触发，比如确认键、串口设置成功，不要循环一直写。

蓝桥杯单片机模板使用说明
========================

一、这个模板的核心思想
--------------------
1. PCA CCF1 产生 1ms 系统节拍，只负责给任务计数，不执行耗时模块。
2. PCA CCF2 负责 LED、数码管、继电器/蜂鸣器刷新，保证显示实时性。
3. 主循环只做业务逻辑，不直接操作 P0/P2/74HC573。
4. 主循环通过 led、seg[8]、b_and_r 这些“影子变量”告诉中断应该显示什么。
5. RTC、ADC、温度、NE555、超声波、串口都已经留好周期入口。
6. PCF8591 数组含义：adc[0]右侧ADC，adc[1]光敏，adc[2]运放，adc[3]电位器，adc[4]DAC。
7. pot_mv 是电位器输入电压，单位 mV，公式为 adc[3] * 5000 / 255。
8. light_mv 是光敏电阻输入电压，单位 mV，公式为 adc[1] * 5000 / 255。
9. dac_mv 是希望 DAC 输出的电压，单位 mV；写 DAC 前会换算成 adc[4] = dac_mv * 255 / 5000。
10. PCF8591_Adc(adc) 每次调用轮流更新一路 ADC，所以单个通道的实际刷新周期约为 PCF8591_TASK_TIME * 4。

二、新题来了优先改哪里
--------------------
1. Display_Proc()：改数码管显示内容，只修改 seg[0]~seg[7]。
2. Key_Proc()：改按键功能，比如切换页面、参数加减、确认保存。
3. Task_Proc()：改模块采样周期或关闭不用的模块。
4. Logic_Proc()：写题目的核心计算、报警判断、状态切换。
5. Led_Proc()：改 LED 指示规则，只修改 led 变量。
6. Relay_Buzz_Proc()：改继电器、蜂鸣器输出，只修改 b_and_r 变量。
7. Uart_Proc()：改串口协议解析和回复内容。

三、常用周期建议
----------------
按键：10ms
ADC/PCF8591：50ms
DS1302：300~1000ms
DS18B20：250~500ms
超声波：150~300ms
NE555：1000ms
数码管扫描：由 PCA CCF2 自动完成，不要放主循环

四、最重要的禁忌
----------------
1. 不要在主循环里直接 HC138(7)、P0=xxx 刷数码管。
2. 不要在中断里读温度、读 IIC、读 DS1302。
3. 不要让函数返回局部数组地址。
4. 不要每轮 while(1) 都读取所有模块，必须用任务周期。
5. 不要把旧题业务变量和报警逻辑留到新题里。

五、默认示例
------------
mode=0：显示时间 HH-MM-SS
mode=1：显示温度和电位器电压 x.xxV
mode=2：显示 NE555 频率
mode=3：显示超声波距离
S4：切换页面
S8/S9：示例阈值加减
串口收到 ?：回复 OK\r\n
这些示例只是为了让模板上电后有东西可看。正式做题时，可以按题目删改。
六、EEPROM参数保存示例
--------------------
1. 模板已经启用 AT24C02：Driver\iic.h 中定义了 EEPROM_AT24C02。
2. EEPROM_LoadParams()：从 EEPROM 读取保存过的参数。
3. EEPROM_SaveParams()：把参数写入 EEPROM。
4. 当前示例保存 demo_threshold 和 dac_mv 两个 16 位参数。
5. EEPROM 中使用魔术字 EEPROM_MAGIC 和简单校验和，防止随机旧数据被误认为有效参数。
6. S12：保存参数到 EEPROM。
7. S13：从 EEPROM 重新读取参数。
8. 新题如果要保存更多参数，就扩展 EEPROM_SaveParams() 和 EEPROM_LoadParams() 里的 buf[]。
9. EEPROM 写入寿命有限，不要在 while(1) 里连续写；建议只在按键确认、串口设置成功等事件发生时写一次。
七、串口字符串输入输出模板
------------------------
1. 串口初始化在 System_Init() 中调用 uart_init()，波特率为 9600bps@12MHz，使用 T2 作为波特率发生器。
2. 串口接收在 uart_0() interrupt 4 中完成，每收到一个字节就存入 RX1_Buffer。
3. PCA 的 1ms 系统节拍负责判断接收空闲时间，超过 UART_IDLE_TIME 没有新字节，就认为一帧字符串接收完成。
4. Uart_Proc() 在主循环中解析 RX1_Buffer，不要在串口中断里解析复杂字符串。
5. 串口发送采用 TX1_Buffer + TI 中断自动续发，主循环只需要调用 Uart_SendString() 或手动组包后 Uart_TxStart()。

当前模板示例命令：
?：回复 OK\r\n
(T?)：查询时间，回复 (T,HHMMSS)\r\n
(V?)：查询电位器和光敏电压，回复 (V,x.xx,x.xx)\r\n
(F?)：查询 NE555 频率，回复 (F,1234)\r\n
(D,2500)：设置 DAC 目标输出 2500mV，合法范围 0~5000，成功回复 OK，否则 ERROR。
(T,235950)：设置时间为 23:59:50，合法范围为 HH<24、MM<60、SS<60。

以后做题时：
1. 如果题目要求查询参数，就在 Uart_Proc() 里增加类似 (X?) 的分支。
2. 如果题目要求设置参数，就增加类似 (X,1234) 的分支，并做数字合法性判断。
3. 如果要回复带变量的字符串，优先使用 Uart_TxClear()、Uart_TxPutString()、Uart_TxPutUInt()、Uart_TxPutVoltage()、Uart_TxStart() 这一套。
4. 如果只回复固定字符串，可以直接 Uart_SendString("OK\r\n")。
八、从标准答案移植复杂串口功能
--------------------------
1. 标准答案可以当“菜谱”，本模板是“厨房”。不要整段覆盖模板串口代码，优先移植命令格式、参数解析和回复格式。
2. 保留模板的底层结构：uart_0() 中断只收发字符，1ms 系统节拍判断接收空闲，Uart_Proc() 在主循环里解析。
3. 新增普通命令时，优先在 Uart_ParseOneCommand(start,end,reply_enable) 里增加 else if 分支。
4. 查询类命令，例如 (X?)，在 reply_enable=1 时用 Uart_TxClear() + Uart_TxPutString() 等函数拼回复。
5. 设置类命令，例如 (X,1234)，先判断格式和数字范围，合法才修改变量，非法必须回复 ERROR。
6. 如果题目要求 (D,2500)(T,235950) 这种连续配置命令，把 UART_MULTI_CMD_ENABLE 改为 1。
7. 连续命令模式默认适合“连续设置参数”，全部成功后统一回复 OK，有一条失败就回复 ERROR。
8. 如果题目要求连续查询，例如 (T?)(V?)，不要直接复制普通查询分支；需要改成拼接总回复，或者扩展发送队列。
9. 从标准答案复制代码时，重点改变量名和数据范围，避免把旧题的报警编号、页面变量、专用参数一起带进新题。
10. 改完串口后必须编译一次；如果打开 UART_MULTI_CMD_ENABLE，也建议临时打开编译确认，再按题目需要决定是否保持开启。
九、LED闪烁模板
--------------
1. 当前模板已经把 L5 报警灯改成 0.2s 闪烁，条件是 alarm_flag=1。
2. 闪烁周期由 main.c 里的 LED_BLINK_TIME 控制，单位 ms；例如 200 表示每 200ms 翻转一次亮灭状态。
3. 1ms 系统节拍只负责更新 LED_Blink_Task 和 led_blink_flag，不直接写硬件。
4. Led_Proc() 只根据 led_blink_flag 决定是否置位 led，例如 L5 对应 0x10。
5. 如果要改成 L6 闪烁，把 Led_Proc() 里的 0x10 改成 0x20；L7 是 0x40，L8 是 0x80。
6. 如果题目要求常亮，不用 led_blink_flag，直接写 led |= 对应位即可。
7. 不要用 Delay_nms() 做闪灯，否则会影响按键、显示刷新和串口处理。
十、主动异常上报模板
------------------
1. 主循环里已经调用 Uart_Report_Proc()，如果题目不用主动上报，可以直接注释掉这一行。
2. Uart_Report_Proc() 默认不会发送，只有 uart_report_flag=1 时才会发送。
3. 推荐在 Logic_Proc() 里判断异常条件，只设置 uart_report_code 和 uart_report_flag，不要直接发串口。
4. 默认上报格式是 [错误码,HHMMSS]\r\n，例如 [500,123456]。
5. 如果要上报 500/501/502 等不同异常，就先写 uart_report_code=500，再写 uart_report_flag=1。
6. 建议只在“异常刚发生”或“状态变化”时置 uart_report_flag，避免异常持续存在时重复刷屏。
7. 如果题目要求带更多数据，例如频率、液位、状态位，就在 Uart_Report_Proc() 里用 Uart_TxPutChar/String/UInt 继续追加字段。
8. Uart_Report_Proc() 会检查 B_TX1_busy，串口正在回复查询命令时不会打断，等空闲后下一轮主循环再上报。
